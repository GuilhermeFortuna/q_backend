## Purpose and current system

Train and compare LightGBM, Random Forest and logistic regression from an existing unfiltered MA Crossover run. Reuse Dramatiq job lifecycle, Postgres persistence, Parquet lake artifacts and q_core-backed backtests. Current `neural/` is an encoder subsystem and remains separate. Existing `backtesting/chart_data.py` exports market_data.parquet with OHLCV and per-entry indicator columns; trades.parquet stores completed trade outcomes. Training reads these frozen artifacts, never a CSV directory or refreshed provider data. The documentation baseline includes the current CSV-export feature commits; if implementation starts from a base without market_data persistence, add that persistence through the normal backtest artifact path within this task. CSV download endpoints are not required by ML training.

## Source, samples and partitions

- Eligible source: completed candle sequential backtest, exactly one original MACrossover entry, manager `or` with empty params, complete frozen bar/indicator/trade artifacts and reconstructable saved configuration. Support the existing day_trade scheduling flag. Reject composites, ML-filtered/tick sources, duplicate/nonmonotonic bars, missing artifacts and ambiguous signal mapping with an actionable reason. Legacy sources may be used only if mapping and saved config are fully verifiable; otherwise ask for a new baseline run.
- Locate each executed entry in the source bar sequence; use its immediately preceding bar as signal_time. Confirm the side matches the original unfiltered signal there using existing MA strategy logic and saved e0 indicator columns. Validate next-open mapping, gaps and timestamp conversion. Never look up feature values at entry_time, use entry_price, or subtract a timeframe duration. Freeze the actual source columns and full-content checksums before fitting, validate a consistent snapshot, and reject concurrent replacement/partial source files; record engine/source revision when available and explicitly mark legacy provenance otherwise.
- Ordered allowlist, defaults and labels are Q-085's. Reuse one `build_entry_features(frame, sides, feature_names)` implementation for training and inference. Resolve e0-prefixed MA columns to canonical names. Closed finite-PnL source trades provide labels; keep actual signal/entry/exit timestamps and side in sample metadata. No resampling of bars or fallback to another provider.
- Train/validation/lockbox are chronological, contiguous bar partitions. Default suggestion is 60/20/20 by bar count; request sends explicit UTC boundaries. Train signal_time < train_end AND exit_time < train_end; validation signal_time in [train_end, validation_end) AND exit_time < validation_end; lockbox signal_time >= validation_end with complete labels within source coverage. Exclude boundary-crossing/unclosed samples and report reasons/counts. Warm-up history may precede a partition, but evaluation starts flat and never trades the warm-up.
- Train requires at least 20 complete samples and at least two of each class. Validation requires at least one complete sample; single-class ROC AUC is null with reason. All chosen features must be present and finite for eligible samples; reject/report incomplete rows rather than fill from future data. An omitted volume feature remains omitted at inference; zero is not automatically missing. Default omit real_volume when unavailable/all zero, with explicit source readiness text.
- Source run configuration must match model use: symbol, timeframe, MA periods/types/threshold, exits, day_trade schedule, costs, point value and sizing recipe including initial capital. Evaluation changes only date range, starts flat and uses frozen source bars. Record a canonical compatibility fingerprint. Labels reflect the baseline's realized trades; do not claim coverage of entries that the baseline never executed.

## Models and immutable persistence

Create `ml_filters/` with classifier adapters, not neural encoders. Each adapter implements `fit(X, y)`, `predict_good_entry_probability(X)`, `dump`, `load`; probability selection resolves the class labelled 1 explicitly. Defaults: LightGBM binary/100 estimators/learning_rate 0.1; RF 200 estimators; logistic regression max_iter 1000. Seed 42, one fitting thread per worker. Expose only these hyperparameters initially: LightGBM n_estimators (integer 1–2000, default 100), learning_rate (finite >0 and <=1, default 0.1), num_leaves (integer 2–256, default 31); RF n_estimators (integer 1–2000, default 200), max_depth (null or integer 1–100, default null), min_samples_leaf (integer 1–100, default 1); logistic C (finite >0 and <=1000000, default 1), max_iter (integer 100–10000, default 1000). Unknown parameters are rejected. Seed is a nonnegative 32-bit integer; users cannot override objective, class semantics, preprocessing or fitting thread count. No automatic hyperparameter search or GPU requirement. Add reproducible LightGBM dependency and keep sklearn/joblib conventions.

Logistic regression uses a StandardScaler fitted on training data only. Tree adapters use a recorded identity preprocessing step. Serialize the complete fitted pipeline and feature order. No refit after validation in v1; the saved training-only model is the exact model selected for later evaluation. Record hyperparameters, RNG seed, runtime/library versions and fitted-byte checksum; content hashes distinguish changed data, labels, preprocessing or fitted state. Publish atomically only after checksummed files are complete. Load only owned lake artifacts through registered adapters, never user paths/uploads. Checksums and runtime compatibility are validated before scoring.

Persist MLFilterRun, MLFilterModelVersion and MLFilterEvaluation records via normal migrations/repositories; job results remain available after Redis expiry. An all-or-nothing training job fits selected algorithms on the same dataset/split, runs validation comparison at threshold 0.50, then publishes ready versions. Failed jobs retain diagnostics and never expose partial models as selectable; replayed delivery does not create duplicate published versions or repeat completed work. Source deletion after publication does not invalidate the frozen dataset/model; no new artifact deletion/archival workflow is needed.

## Comparison and final evaluation

Implement a reusable `EntryFilteredStrategy` wrapper after CompositeEntryStrategy produces final signal columns. This unregistered internal wrapper supports validation comparisons before Q-087 exposes the variant. Score only candidate entry bars; rejected/nonfinite-feature candidates have entry and strength zero. Accepted entries retain the original strength (probability does not change sizing). Exit arrays, exit_strategy and chart indicators pass through unchanged. Invalid artifact/model scores fail the job; warm-up/nonfinite feature candidates are explicitly not-ready, rejected and counted. Never filter buy_signal/sell_signal before stance combination.

Ensure the wrapper suppresses entries before train_end while retaining any history needed for indicator warm-up. Run baseline and filtered engines from identical flat starts on each validation partition, with preceding source history for warm-up and the same costs, capital, sizing, scheduling and partition-end close policy. End-of-partition closure is an evaluation convention applied to both runs and recorded; no source outcomes beyond the boundary contribute. Measure actual engine trade/equity results, never sum retained source PnL. Classification is an auxiliary report on completed source samples and is labelled separately from candidate acceptance and actual executed trades.

POST comparisons uses only versions sharing one frozen dataset and reuses validation, never lockbox. POST evaluations selects exactly one model/threshold, atomically freezes and consumes the dataset lockbox before dispatch, and evaluates baseline versus filtered once. Identical requests/delivery retries resume the same record; a different tuple is rejected even after failure. Save classification/engine metrics, counts and equity/trade artifacts. A user can have inspected the existing source run's full period already: describe this tail as reserved by this workflow, not proof it was historically unseen. Backtesting remains research exploration; v1 does not prevent users inspecting market data or manually creating a new dataset.

## Acceptance criteria

1. A fixture whose entry candle differs sharply from its signal candle trains on the latter; appending future bars cannot change existing features/scores for a frozen model. Timestamp gaps and Brazil/UTC conversion map correctly by position.
2. Split-boundary trades, missing features, unavailable volume, two-class minima and source eligibility have exact visible rejection counts and reasons. Preprocessing never sees validation/lockbox rows.
3. All three algorithms fit/load through one interface with explicit positive-class mapping, ordered features and reproducible provenance; fitting and loading yield equivalent scores within declared library tolerance.
4. Actual validation reruns demonstrate independent exits, flat-start/warm-up semantics, unchanged sizing and costs, and candidate counts distinct from executed trades.
5. Failed/retried jobs, corrupted artifacts, missing sources, persisted history after Redis expiry and concurrent lockbox requests never publish partial successes or evaluate conflicting tuples.
6. Focused ML, job, DB and API suites plus contracts-check and canonical backend CI pass without GPU, Wine or desktop requirements.
